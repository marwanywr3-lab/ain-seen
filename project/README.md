# عين سين

مسابقة عربية لفريقين ومقدم إلزامي. React 18 وTypeScript، مع Workers وD1 وDurable Objects في Cloudflare. الواجهة منشورة على GitHub Pages، والخادم يحتاج نشرًا منفصلًا.

## الاستخدام

المقدم ينشئ جلسة ويحصل على رمز من ٨ أحرف. يدخل المشاركون بأسمائهم والرمز، ثم يعيّن المقدم القائدين ويبدأ المباراة. شاشة العرض اختيارية. القائد فقط يجيب ويضغط البزر ويستخدم الكروت.

بوابة الأسئلة **عامة للجميع للتصفح والبحث والتصدير** دون حساب أو كلمة مرور. تعديل مكتبة الأسئلة المشتركة يبقى محميًا للمسؤول. تعرض البوابة الأسئلة الأصلية وتتيح تصديرها حتى قبل نشر الخادم؛ لا تدعي حفظ التعديلات على الخادم دون نجاح الاستجابة. لا يوجد حقل عنوان خدمة في واجهات اللاعبين أو البوابة.

## لماذا ظهر خطأ إنشاء الجلسة؟

النسخة السابقة لم تحتوي عنوان API. الرسالة كانت تخرج من الواجهة قبل أي طلب إلى الخادم. الحل البرمجي يقرأ الآن العنوان من `config.json` وقت التشغيل. **الملف الفارغ لا ينشر خادمًا**؛ لا تعمل الغرف قبل نشر Worker فعليًا.

## النشر الآلي

المستودع يحفظ المصدر في `project/` والواجهة المبنية في الجذر.

1. أضف مفتاح Cloudflare إلى GitHub: Settings → Secrets and variables → Actions → New repository secret. اسم السر `CLOUDFLARE_API_TOKEN`. لا ترسله في المحادثة ولا تضعه في الكود أو أي متغير VITE_.
2. شغّل Actions → Deploy Cloudflare and connect game → Run workflow.
3. ينفّذ workflow ترقية قاعدة D1 ونشر Worker، ثم يقرأ عنوان workers.dev الفعلي من نتيجة النشر ويكتب `config.json` في الموقع. يُعاد نشر Pages عند commit إعداد الاتصال، دون طلب عنوان من اللاعبين.

معرّف الحساب والقاعدة مضبوط في `wrangler.jsonc`. يمكن تجاوزهما بمتغيرات المستودع `CLOUDFLARE_ACCOUNT_ID` و`D1_DATABASE_ID`. يجب أن يملك المفتاح صلاحيات نشر Workers وDurable Objects وتعديل D1 في الحساب المحدد. التصفح لا يحتاج Cloudflare Access. تبقى الكتابة مقفلة ما لم تضبط Access للمسؤول.

لم يُتحقق من نشر خادم الإنتاج في جلسة التطوير؛ يلزم نجاح workflow وإرجاع /health واختبار إنشاء غرفة على العنوان المنشور قبل اعتبار التشغيل مكتملًا.

## التشغيل المحلي

من مجلد المصدر، باستخدام Node.js 24:

```sh
npm ci
npm run dev
```

يشغّل هذا Vite ومحاكي Cloudflare مع الأسئلة الأصلية. لا يحتوي المنتج على بيانات أسئلة وهمية. fixtures الاصطناعية تخص الاختبارات فقط.

```sh
npm run check
npm test
npm run worker:build
npm run integration
npm run build
```

اختبار التكامل يفحص الاتصال والأدوار وتعيين القادة والتوقيت والخطف والنقاط وحفظ البيانات في D1. `dist/` يحتوي ملفات الواجهة المنشورة، و`public/config.json` مصدر إعداد الاتصال. ملف runtime يقبل HTTPS فقط، ولا يخمّن عنوان Worker.

## التخزين

D1: الأسئلة، والغرف، والفرق والنقاط والكروت، وأعضاء الغرف وجلساتهم، وسجل النقاط والأحداث. تحفظ مفاتيح الجلسات في D1 كبصمات SHA-256. Durable Objects تدير الحالة الفورية والبزر والمؤقتات وتحفظها أيضًا. عند تعذر مزامنة D1 مؤقتًا تُعاد المحاولة بعد ١٥ ثانية. تنتهي الغرف بعد ٢٤ ساعة من آخر إجراء ناجح.

migrations إضافية ولا تحذف الأسئلة القائمة. `0003_room_members.sql` تدعم انضمام المشاركين بالرمز والاسم.

## العرض

الشعاران بخلفية لون الموقع. لم تتغير keyframes الأنيميشن في هذا التحديث؛ أزيلت طبقة انتظار الصورة المعطلة للنقر فقط. تحترم الحركة إعداد تقليل الحركة. لا توجد موسيقى أو أصوات. خط Cairo مرخص SIL OFL، ونسخة الترخيص ضمن licenses/.
