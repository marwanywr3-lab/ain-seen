# عين سين

لعبة مسابقات عربية لفريقين، بمقدم إلزامي. React 18 + TypeScript strict + Cloudflare Workers/D1/Durable Objects. واجهتان ثابتتان: `index.html` للعبة و`admin.html` لبوابة الأسئلة، صالحتان للاستضافة على GitHub Pages.

## تخزين بيانات اللعبة في D1

| الجدول | المحتوى |
| --- | --- |
| question_bank | الأسئلة والتعطيل وإصدار المكتبة |
| game_rooms | الغرف وحالة المباراة والفائز والمؤقت ونسخة الأسئلة |
| room_teams | الأسماء والنقاط والكروت وعين التحدي |
| room_sessions | بصمات SHA-256 لمفاتيح أدوار المقدم والقائدين |
| room_score_audit | إضافات وخصومات النقاط وأسبابها |
| room_events | سجل إجراءات المباراة وانتقالات الوقت |

Durable Objects تنسق البزر والمؤقتات وتحفظ الحالة الفورية. D1 تحفظ نسخة محدثة قابلة للاستعلام. إذا تعذر حفظ D1 مؤقتًا تبقى حالة Durable Object محفوظة وتُعاد المزامنة تلقائيًا بعد ١٥ ثانية. لا توجد معاملة موزعة ذرية بين المنتجين؛ مرجع التزامن أثناء اللعب هو Durable Object.

الترقية `0002_rooms_and_matches.sql` تضيف الجداول دون حذف الأسئلة. ملف الإنشاء الكامل يشمل مكتبة الأسئلة والجداول الستة. تنفيذ الإنشاء المتكرر لا يستبدل بيانات الأسئلة المعدلة. عند انتهاء صلاحية الغرفة تُحذف بياناتها المرتبطة وتبقى مكتبة الأسئلة. لا تحفظ مفاتيح الدخول الخام في D1.

## ما تم تنفيذه

- ١٢ فئة × ٣ قيم = ٣٦ خانة. الأسئلة الـ١٢٠ التي قدمها المستخدم ضمن قاعدة البداية.
- وضع الشاشة الواحدة (المقدم يسجل قرارات الفريقين) ووضع جوال لكل قائد، وروابط مستقلة للمشاهدين وشاشة العرض.
- المقدم ينشئ الغرفة ويكشف الأسئلة ويستأنف الجولات وينهي المباراة. القائد وحده يختار ويجيب ويستخدم البزر والكروت في وضع الجوالات.
- ٢٠ ثانية للسؤال، ٧ ثوانٍ لانتظار الخطف، ثم ٧ ثوانٍ للإجابة. الفاصل ٥ ثوانٍ بعد أول بزر.
- عين التحدي قبل كشف السؤال، مرة لكل فريق، بثواب وعقوبة مضاعفين. الخطف يحتسب القيمة الأصلية وعقوبته نصفها. النقاط السالبة مسموحة.
- كل كرت مرة لكل فريق: عين حارة للمنافس، والاستبدال وحذف خيارين للفريق النشط. الكروت للسؤال الأساسي فقط. الاستبدال لا يعيد الوقت ويلغي حذف الخيارات السابق.
- اختيار الفريق البادئ بالقرعة ثم تناوب ثابت. سؤال فاصل محجوز من مخمخ لا يستخدم في اللوحة أو البدائل.
- خادم الغرفة هو مرجع الحالة والوقت، مع حسم ذري للبزر وحراسة الإصدارات وتكرار الطلبات. الإنذارات تستمر دون اتصال العملاء.
- حفظ الحالة واستعادتها بعد تحديث الصفحة أو إعادة الاتصال. رابط قائد جديد على جهاز آخر يستبدل اتصال القائد السابق.
- غرف تنتهي بعد ٢٤ ساعة من آخر إجراء ناجح؛ حد ٦٤ اتصالًا وحد إنشاء غرف لكل عنوان شبكة.
- إيقاف مؤقت بين الجولات فقط. المؤقت يستمر عند انقطاع القائد أو المقدم، وتبقى إجراءات المقدم حصرية له.
- بوابة إدارة: بحث وتصفية، إضافة وتعديل ومعاينة وتعطيل وإعادة تفعيل، استيراد وتصدير JSON، وحراسة تعارض التعديلات. المباريات الجارية تحتفظ بنسختها من الأسئلة.
- الإجابات والأسئلة الاحتياطية لا ترسل للاعبين قبل الحسم. المقدم مصرح له بمشاهدة الإجابة.
- الهوية والشعاران المعتمدان، خط Cairo محلي، وحركات الفتح وبداية القيم والدور والنهاية دون أي صوت، مع احترام تقليل الحركة.

## التشغيل المحلي

Node.js 24:

```bash
npm ci
npm run dev
```

يفتح Vite ومعه محاكي Cloudflare محلي وقاعدة أسئلة الاختبار. عنوان الواجهة يطبعه أمر التشغيل. معرّف الإدارة التجريبي في محاكي التطوير فقط؛ لا يضاف إلى نشر الإنتاج. لا يتضمن المنتج أسئلة وهمية. Fixtures الاختبارات فقط مصطنعة.

```bash
npm run check
npm test
npm run worker:build
npm run integration
npm run build
```

`integration` يشغّل Worker وD1 وDurable Objects وWebSockets حقيقية داخل Miniflare، ويختبر الصلاحيات ومنع تسريب الإجابة والخصومات وتكرار البزر والإيقاف وانتهاء مؤقت فعلي وإعادة الاتصال وتعارض تعديل الأسئلة. ينتظر الاختبار نحو ١١ ثانية لفحص المؤقت.

## النشر على Cloudflare

1. أنشئ D1 باسم `ain-seen` في حسابك، واحتفظ بمعرّفها. لا يحتوي المستودع على معرّف قاعدة مزيف.
2. جهّز نطاق الخدمة وحماية Cloudflare Access للمسار `/admin/*` بسياسة تسمح لحساب الإدارة فقط. اسمح بطلبات CORS المسبقة OPTIONS في إعداد Access. تحقّق من توافق إعدادات cookies وCORS عند استخدام نطاقين مختلفين، ويفضل وضع الواجهة والخدمة تحت نطاقك نفسه لتفادي منع cookies العابرة للمواقع.
3. اضبط إعدادات النشر التالية في بيئة GitHub `production` أو بيئة الطرفية:

| الإعداد | الاستخدام |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | معرّف حساب Cloudflare |
| `D1_DATABASE_ID` | معرّف قاعدة D1 الفعلية |
| `ALLOWED_ORIGINS` | أصول الواجهات المسموحة، مفصولة بفواصل، دون مسارات |
| `ACCESS_TEAM_DOMAIN` | نطاق فريق Access، دون https أو مسار |
| `ACCESS_AUD` | Audience تطبيق Access |
| `CLOUDFLARE_API_TOKEN` | سر نشر Cloudflare في GitHub Secrets فقط |

4. نفذ workflow `Deploy Cloudflare API` أو `npm run deploy`. ينشئ إعداد نشر محليًا غير متتبّع، ويطبق migration البداية ثم ينشر Worker. النشر يفشل صراحة إن نقص إعداد مطلوب. سيطبع Cloudflare عنوان الخدمة الفعلي.

لا تضبط `ENVIRONMENT=development` أو `DEV_ADMIN_TOKEN` في الإنتاج. الدخول الإداري يتحقق من JWT وتوقيعه وissuer وaudience؛ لا يثق بهوية مرسلة من المتصفح.

## النشر على GitHub Pages

1. ارفع الملفات إلى مستودع جديد، ثم اختر GitHub Actions كمصدر Pages.
2. اضبط متغير المستودع `VITE_API_URL` على عنوان الخدمة المنشورة الحقيقي. عند نقصه يجري الفحص والبناء لكن يُتجاوز نشر Pages تلقائيًا.
3. أضف أصل Pages إلى `ALLOWED_ORIGINS` في إعداد خدمة Cloudflare وأعد نشرها.
4. workflow `Validate and publish GitHub Pages` يفحص الأنواع والاختبارات والتكامل ويبني الواجهة وينشر `dist/`.

المسارات نسبية، لذا يعمل النشر داخل مسار المستودع. بوابة الأسئلة لها مستند مستقل `admin.html` ويمكن استضافة مخرجاتها على نطاق مستقل. لا تضف مفاتيح Cloudflare إلى متغيرات تبدأ بـVITE_.

## الدخول والاستخدام

- المقدم ينشئ غرفة ويحتفظ بجلسته على جهازه.
- يرسل رابط كل قائد لصاحبه فقط، ورابط المشاهدة للشاشة والأعضاء. مفاتيح الأدوار تحفظ في جزء fragment من الرابط ثم تنقل لتخزين الجهاز؛ لا توضع في query string.
- في وضع الجوالات ينتظر اتصال القائدين ثم يبدأ. يستطيع المشاهد متابعة الأسئلة والنقاط دون أي تحكم.
- يجب استخدام HTTPS في النشر العام. إذا مُنع نسخ الرابط آليًا، يمكن نسخه من الحقل الظاهر.
- إظهار أدوات المقدم وإخفاؤها يغيّر العرض فقط؛ رابط المشاهدة هو الوسيلة الصحيحة لشاشة جمهور مستقلة.

## حدود التحقق الحالية

اختبارات محلية ناجحة وفحص واجهة داخل المتصفح. لم يُنشأ مستودع GitHub أو تُنشر موارد Cloudflare في جلسة التنفيذ بسبب غياب إمكانية إنشاء المستودع في الموصل وغياب تسجيل الدخول في المتصفح المتاح. يلزم إكمال ذلك قبل وصف النسخة بأنها منشورة أو مُختبرة على الإنتاج.

حُفظت نصوص الأسئلة المعتمدة دون تصحيح محتواها؛ فحص البنية لا يساوي تدقيق الحقائق. يلزم تدقيق الأسئلة المرتبطة بمعلومات زمنية أو روايات مختلف فيها قبل الإطلاق العام. نشر المصدر علنًا يجعل ملف أسئلة البداية متاحًا لمن يتصفح المستودع؛ حماية واجهة اللعب تمنع كشف الإجابات عبر API للمشاركين فقط.

خط Cairo مرخص وفق SIL OFL؛ الترخيص في `licenses/`. لا توجد موسيقى أو مؤثرات صوتية حاليًا.
